# Контракты

Источник правды для всей системы. Код генерируется отсюда, руками
сгенерированное не правится.

```
contracts/
├── soap/decider-v1.wsdl      ядро ← оболочка: команда + состояние → решение
├── idl/enrichment-v1.idl     events → core: обогащение событий по IIOP
└── errors/errors.yaml        единый список кодов отказа
```

## Главное правило

**Каждая операция объявляет три вещи:** команду, состояние, необходимое для
решения, и форму решения.

Ядро на Pascal не делает ввода-вывода: под DOS его сделать нечем. Всё, что
нужно для решения, приходит в запросе. Отсюда следует то, что в обычном
проекте выглядело бы избыточным:

**Все поля внутри типов, оканчивающихся на `Context`, обязательны.**
Необязательное поле состояния означает, что однажды придёт запрос без него, и
ядро примет решение по неполным данным. Обнаружится это не в тестах, а на
реальных данных. Пропуск обязан ломаться маршалингом, а не оборачиваться
значением по умолчанию. Проверяется валидатором.

**Ядро обязано вернуть `INSUFFICIENT_CONTEXT`,** если обнаружит нехватку
данных, а не додумать значение. Наличие этого кода тоже проверяется.

## Цена поля

Линия между оболочкой и ядром даёт **11 520 Б/с**, и каждый байт состояния
вычитается из пропускной способности записи напрямую
(см. [PHASE0-FINDINGS.md](../docs/PHASE0-FINDINGS.md), S2). Состояние
объявляется минимально достаточным. Это предмет обязательного ревью, а не
вкуса.

## Кодировки

**В IDL любое поле с человеческим текстом — `wstring`, не `string`.** Тип
`string` в CORBA байтовый и кириллицу не принимает: вызов падает с
`DATA_CONVERSION` в рантайме, на первом реальном пользователе, а не при
компиляции. Идентификаторы остаются `string` с явной пометкой «ASCII по
контракту». Проверяется валидатором по именам полей.

В SOAP такой проблемы нет: XML передаётся в UTF-8.

## Версионирование

Версия в имени файла. Совместимое изменение — добавление необязательного поля
вне `Context`. Ломающее — новая мажорная версия рядом со старой, обе живут,
пока не мигрируют все потребители.

## Проверка

```bash
./sonder contracts
```

Валидатор проверяет то, чего не выражает схема: уникальность кодов отказа,
наличие решающей стороны у каждого кода, обязательность полей состояния,
отсутствие `string` в текстовых полях IDL, наличие ответа у каждой операции.

Валидатор, который всегда зелёный, бесполезен, поэтому у него есть
самопроверка: в копию контрактов по одному вносятся восемь реальных дефектов, и
проверяется, что на каждом он падает и говорит по делу.

```bash
./sonder contracts-selftest
```
