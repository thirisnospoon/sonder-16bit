# Спайки фазы 0

Одноразовый код, снимающий технический риск до того, как он превратится в
переписывание. Наружу из спайка выходят **числа и выводы**, а не код: результаты
попадают в [docs/PHASE0-FINDINGS.md](../docs/PHASE0-FINDINGS.md) и заменяют
пометки `[спайк]` в [docs/TURBOCORE.md](../docs/TURBOCORE.md).

Спайк не обязан быть красивым, но обязан быть **воспроизводимым** и выносить
**однозначный вердикт**.

## Как запускать

Всё исполняется в образе тулчейна, на хосте ничего ставить не нужно:

```bash
docker build -f ops/toolchain/Dockerfile -t sonder/dos-toolchain:3.2.2 .
```

```bash
docker run --rm -v "$PWD:/work" sonder/dos-toolchain:3.2.2 bash spikes/s1-fibers/run-all.sh
```

Первая сборка образа долгая: тянется 84 МБ исходников FPC и 143 МБ Open Watcom,
затем собирается кросс-компилятор и RTL под каждую модель памяти. Загрузки
кэшируются в cache-mount BuildKit, повторные сборки быстрые.

## Почему вердикт выносится по файлу, а не по коду возврата

DOSBox не обязан честно пробрасывать код возврата DOS-программы наружу
(см. [RISKS.md](../docs/RISKS.md), R3). Поэтому каждый спайк пишет отчёт в
формате TAP в примонтированный каталог, а решение принимает скрипт снаружи
эмулятора. Тот же приём потом используется в CI для настоящих тестов
(см. [TURBOCORE.md](../docs/TURBOCORE.md) §11).
