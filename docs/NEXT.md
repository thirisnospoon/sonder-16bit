# Что дальше

Точка продолжения. Обновляется в конце сессии; читается в начале
следующей.

**Состояние на 2026-09-04:** `./sonder verify` зелёный, ветка `main`,
последний коммит — второе мнение о правилах регистрации.

## 1. Открытый гейт: сутки фаззинга

Единственный формально незакрытый пункт всего плана, и зависит он не от
работы, а от машинного времени.

```
./sonder soak-total
```

На момент остановки — **23,3 ч из 24 (97%)**, под DOSBox своё уже
набрано (6,31 из 6 требуемых). Контейнер `sonder-native` молотит сам с
политикой `unless-stopped`; если он не пережил перезагрузку, поднять
заново:

```bash
./sonder soak --minutes 120 --target native
```

Когда наберётся 24 — гейт фазы 5 закрыт, и это последнее, что мешает
объявить фазы 0–10 пройденными целиком.

## 2. Второе мнение: осталось пять операций из семи

Механика готова и работает ([ADR-0022](adr/0022-domain-second-opinion.md)).
Накрыты `createPost` и `registerUser` — 1261 случай, согласие на всех.

Осталось: **`createComment`, `deletePost`, `followUser`, `unfollowUser`,
`banUser`.**

Порядок брать по РОДУ правил, а не по алфавиту — смысл в том, чтобы
каждая следующая операция добавляла новый вид проверки:

| Операция | Что нового приносит |
|---|---|
| `deletePost` | владение и **идемпотентность**: повторное удаление принимается и не порождает событий |
| `banUser` | **ранги ролей** (`RoleOutranks`): модератор не банит админа |
| `createComment` | контекст **чужого объекта**: пост существует, виден, не удалён |
| `followUser` / `unfollowUser` | самоподписка и контекст цели |

Что делать для каждой (полчаса на операцию, механика одинаковая):

1. `dosnode/tools/mkcases.pas` — добавить `EmitXxx` и `XxxCases`, писать
   `contracts/generated/domain/<операция>.tsv`. Не забыть: **границы
   циклов при нулевой длине** — `for I := 0 to Len - 1` при `Len = 0` и
   типе `Word` даёт `0..65535` и роняет программу (уже ловилось).
2. `ops/ci/gen-domain-cases.sh` — добавить имя в список файлов.
3. `dosnode/prolog/<операция>.pl` — правила ЗАНОВО по контракту и ADR, не
   срисовывая с Паскаля. Общее берётся из `rules.pl`; если нужного
   предиката там нет — добавить туда, а не копировать.
4. `ops/ci/domain-crosscheck.sh` — вызов `run_op`.
5. `ops/ci/falsify/domain-crosscheck.sh` — новый дефект, характерный
   именно для этой операции (для `deletePost` напрашивается сломанная
   идемпотентность, для `banUser` — перепутанные ранги).
6. `./sonder verify` → коммит. **Дрейф упадёт до коммита** — это
   заложенное поведение: порождённый файл обязан лежать под версией.

Проверить баланс корпуса перед коммитом, иначе ветки останутся
непройденными:

```bash
awk -F'\t' '!/^#/ {print $NF}' contracts/generated/domain/<файл>.tsv | sort | uniq -c | sort -rn
```

## 3. Что ещё лежит предложенным, но не начатым

Из четырёх «дичей», обсуждённых в сессии, сделана одна (Пролог).
Остальные — по убыванию силы:

**SHA-256 на 8086-ассемблере и подписанные команды.** Закрывает
настоящую дыру: ядро сейчас верит оболочке на слово — та говорит
«команда от пользователя u-1», и проверить это ядру нечем. С подписью
проверяет само. Векторы NIST. Вопрос «нужен ли асм вместо Паскаля»
решается замером, а не верой. Оценка 5 д.

**Шлюз NNTP.** Отличается от IRC не носителем, а **формой данных**:
Usenet — статьи с ветками и `References`, а не поток строк. Домену
пришлось бы отдать те же посты в другой форме. Аутентификация своя
(`AUTHINFO`), приватность не страдает. Оценка ~4 д.

**Кадры с CRC-16 поверх вебсокета.** Браузер говорит с оболочкой тем же
проводным форматом, что и DOS-нода, и проверяется теми же эталонными
кадрами. Доказывает, что кодек кадров не знает своего носителя.

## 4. Мелочи, замеченные и отложенные

* **Свод печатает всех авторов подряд** — 545 строк на настоящих
  данных, никакого «топ-N». Это продуктовое решение, а не дефект;
  трогать без спроса нельзя.
* **Пропущенная ночь свода не навёрстывается** (машина была выключена).
  Записано в [ADR-0020](adr/0020-digest-on-a-schedule.md) как принятая
  цена; догоняющий счёт — отдельная задача, и делать его молча хуже, чем
  не делать.
* **15 фальсификаций живут без своего скрипта** — внести дефект там
  значит поменять контракт, порог или образ. Перечислены в
  `ops/ci/falsify/run.sh`; каждая проверена руками по одному разу. Это
  ровно тот класс, который гниёт: `TcLog` в фальсификации слоёв так и
  сгнил.
* **Покрытие доменных правил на `i8086-msdos` нечем измерить числом** —
  открытый вопрос, записан в [ENGINEERING.md](ENGINEERING.md).

## 5. Как поднять состав после перерыва

```bash
./sonder up                # состав целиком; порядок сборки образов внутри
./sonder verify            # все проверки, минуты
./sonder falsify           # быстрые фальсификации, секунды
./sonder falsify-slow      # плюс требующие образов и состава
```

Шлюз IRC живёт на `127.0.0.1:6667`; войти настоящим клиентом:

```bash
irssi -c 127.0.0.1 -p 6667 -w <пароль> -n <ник>
```

Написанное в `#feed` становится постом и идёт через ядро на Паскале;
лента приходит туда же той же рассылкой, что и в браузер.
