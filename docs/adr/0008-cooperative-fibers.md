# ADR-0008. Стековые файберы, кооперативно, с вытеснением за флагом

**Статус:** Принято; обоснование изменено [ADR-0011](0011-pascal-domain-core.md)
**Дата:** 2026-09-01

> Файберы обслуживают не пользовательские сессии, а одновременные
> команды: пока ответ передаётся по линии, следующая команда уже
> принимается и обсчитывается. Выигрыш примерно двукратный, а не на
> порядок. Техническая часть решения не меняется.

## Контекст

В реальном режиме DOS нет потоков. Нужно обслуживать до двенадцати сессий в
одном процессе. В диалекте TP7 нет ни замыканий, ни исключений, поэтому
стандартный приём современных рантаймов — трансформация в машину состояний —
недоступен: писать её пришлось бы руками на каждом вызове.

## Решение

Стековые файберы с ручным переключением контекста на inline asm. Все стеки —
статический массив в сегменте данных, `SS` не меняется, переключается только
`SP`. Планирование round-robin, без приоритетов. Каждое ожидание имеет
обязательный дедлайн.

Вытеснение по прерыванию таймера реализуется отдельным режимом за флагом
компиляции и включается только при `InDOS = 0`, поскольку DOS не реентерабелен.
Значение по умолчанию — кооперативный режим.

## Последствия

- Прикладной код читается линейно: `Await` вместо ручной машины состояний.
- Неизменный `SS` устраняет весь класс ошибок с сегментами и указателями на локальные переменные.
- Предел конкурентности — константа компиляции: тринадцатая сессия получает отказ, а не порчу памяти. Это документированное свойство, а не дефект.
- Длинный вычислительный участок без точки переключения блокирует всех. Смягчается сторожевым таймером, который такие участки находит и логирует.
- Каждая функция обязана документировать наличие точек переключения — постоянная нагрузка на дисциплину.
- Ассемблерное переключение — самая непрозрачная часть проекта. Требует отдельного разбора в `docs/CONTEXT-SWITCH.md` и канареечных проверок в отладочной сборке (риск R8).

## Рассмотренные альтернативы

**Машина состояний вручную.** Отклонено: логика сессии BBS в таком виде
нечитаема и неподдерживаема.

**Один процесс DOSBox на сессию.** Отклонено: см. ADR-0007.

**Полностью вытесняющий планировщик.** Отклонено как значение по умолчанию:
нереентерабельность DOS делает его источником трудновоспроизводимых сбоев.
Остаётся опциональным режимом с собственным набором тестов.
