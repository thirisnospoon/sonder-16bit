# ADR-0006. Экраны NODE-7 собираются XSLT на стороне Java

**Статус:** Отменено [ADR-0011](0011-pascal-domain-core.md)
**Дата:** 2026-09-01

> Решение потеряло предмет: у NODE-7 больше нет экранов. DOS-нода стала
> доменным ядром без пользовательского интерфейса, отрисовывать нечего.

## Контекст

NODE-7 живёт в 640 КБ и обслуживает до двенадцати сессий. Разбор произвольного
XML и вёрстка макета на стороне DOS означают DOM-подобные структуры и логику
переноса строк в самом дефицитном месте системы. Одновременно линия узкая, и
каждый лишний байт стоит миллисекунд.

## Решение

`core` отдаёт канонический XML. Преобразование `contracts/screens/*.xsl`
(XSLT 1.0) превращает его в готовый текстовый экран 80x25 ещё в Java. NODE-7
получает почти готовый буфер: потоковый разбор, никакого DOM, никакой вёрстки.

## Последствия

- Пик памяти на NODE-7 снижается кратно; освободившееся идёт на число сессий.
- Макеты экранов лежат рядом с контрактами, версионируются и покрываются golden-тестами на стороне Java — там, где тесты быстрые.
- Изменение макета не требует пересборки DOS-бинарника.
- XSLT 1.0 неудобен: нет группировки, ограничены строковые функции. Часть логики придётся выносить в предварительную подготовку XML.
- Появляется зависимость макета от серверного релиза: старый бинарник должен корректно принимать новый экран. Решается версией в заголовке кадра.

## Рассмотренные альтернативы

**Вёрстка на стороне Pascal.** Отклонено: дороже всего именно там, где памяти
меньше всего.

**Готовый JSON и разбор на Pascal.** Отклонено: экономит немного по сравнению с
XML, но лишает нас WSDL как машинного контракта для кодогенерации.

**Шаблонизатор на Java вместо XSLT.** Работало бы, но XSLT здесь и уместен
исторически, и достаточен технически — а главное, он тоже часть контракта.
