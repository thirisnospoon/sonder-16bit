# ADR-0011. Доменное ядро живёт в Pascal, Java — императивная оболочка

**Статус:** Принято
**Дата:** 2026-09-01
**Заменяет:** [ADR-0002](0002-hexagonal-core.md)
**Отменяет:** [ADR-0006](0006-xslt-screen-rendering.md)
**Изменяет:** [ADR-0007](0007-serial-mux-transport.md), [ADR-0008](0008-cooperative-fibers.md) в части обоснования

## Контекст

ADR-0002 помещал доменное ядро в Java, а DOS-ноду делал вторым клиентом:
пользователи заходили бы по telnet и видели текстовый интерфейс. Отсюда росли
экран 80×25, отрисовка через XSLT, граница кодировок и telnet-сервер в гейтвее.

Это не то, ради чего проект затевался. Ценность конструкции не в том, что к
соцсети есть ещё и текстовый клиент — таких можно написать сколько угодно на
чём угодно. Ценность в том, что **решения принимает шестнадцатибитный код**.

При этом Pascal под DOS не имеет и не может иметь доступа к PostgreSQL:
ни драйвера, ни сети, ни разумного способа их получить.

## Решение

Доменное ядро переезжает в Pascal и строится как **чистая функция принятия
решения**. Java становится императивной оболочкой вокруг него.

```
команда (REST)
   → Java: загружает состояние, нужное для решения
   → SOAP: команда + состояние  →  NODE-7
   → NODE-7: применяет правила, возвращает Решение
   → Java: сохраняет решение одной транзакцией
```

Решение — это либо принятие с перечнем доменных событий, либо отказ с кодом
ошибки из `contracts/errors/errors.yaml`. Никакого ввода-вывода на стороне
Pascal: всё, что нужно для решения, приходит вместе с командой.

Инварианты, переезжающие в Pascal: уникальность ника и его формат, запрет
подписки на себя, идемпотентность удаления, права ролей, ограничения частоты,
правило «забаненный не создаёт контент, но его сессии живут до явного отзыва».

Java сохраняет за собой: HTTP, авторизацию сессий, хранение, проекции чтения,
конвейер событий, доставку realtime.

## Последствия

**Чтение не идёт через DOS.** Запросы на чтение обслуживаются read-model
напрямую. Через последовательную линию проходят только команды записи, и
измеренный в S2 потолок 11 520 Б/с ограничивает только их. Примерно десять
операций записи в секунду на всё приложение — это узкое место системы, оно
осознанное и измеримое.

**Ядро становится детерминированным.** Решение — функция от команды и
переданного состояния, без обращений наружу. Отсюда:

- логика проверяется на нативном таргете тысячами случаев в секунду, а не через эмулятор; дуальная компиляция из [ADR-0005](0005-fpc-dual-target.md) превращается из удобства в основной способ работы;
- к инвариантам применимо property-тестирование;
- любой отказ воспроизводится из записанной пары «команда + состояние».

**Каждая команда обязана объявить, какое состояние ей нужно.** Это входит в
контракт WSDL и проверяется: Java не имеет права послать команду, не приложив
объявленного состояния. Ошибиться здесь означает принять решение по неполным
данным, поэтому проверка обязательна, а не желательна.

**Согласованность.** Состояние загружается Java до вызова и может устареть к
моменту решения. Java сохраняет решение с проверкой версии агрегата; при
расхождении команда переигрывается. Это обычная оптимистическая блокировка, и
она здесь неизбежна.

**Что удаляется из проекта:** экран 80×25 и весь экранный движок, отрисовка
через XSLT, telnet-сервер в гейтвее, граница кодировок CP866, многосессионная
BBS. Соответствующие разделы уходят из ARCHITECTURE.md и TURBOCORE.md.

**Что остаётся без изменений:** модель памяти `large`, арены, кадрирование,
мультиплексор, CRC, стек SOAP и XML, все три пройденных спайка. Они про память,
файберы и транспорт, а не про интерфейс.

**Обоснование файберов слабеет и становится честнее.** ADR-0008 опирался на
шестнадцать одновременных пользовательских сессий. Теперь файберы дают
конвейеризацию поверх медленной линии: пока ответ на одну команду
передаётся, следующая уже принимается и обсчитывается. По измерениям S2 это
примерно двукратный выигрыш, а не порядок. Если бенчмарк Ф10 покажет, что
выигрыш меньше ожидаемого, у нас есть документированное развитие — держать в
Pascal тёплый индекс состояния в дальней куче, тогда файберы обслуживают ещё и
поток его обновлений. К этому возвращаемся по измерению, а не заранее.

**SOAP меняет направление.** Java становится клиентом, NODE-7 — сервером.
Гейтвей превращается из telnet-сервера в мост «SOAP ↔ последовательная линия».

## Рассмотренные альтернативы

**Оставить ядро в Java, DOS как второй клиент (ADR-0002).** Отклонено: DOS-часть
оказывается декоративной, а проект теряет главное утверждение.

**Ядро в Pascal с прямым доступом к БД.** Невозможно: под DOS нет ни драйвера
PostgreSQL, ни сетевого стека. Написание своего — отдельный проект с иным
уровнем риска.

**Ядро в Pascal с тёплым индексом состояния в памяти.** Сильнее обосновывает
файберы и наполняет смыслом 599 КБ дальней кучи, но добавляет задачу
согласованности индекса с базой. Отложено до измерения, зафиксировано выше как
известный путь развития.

**Разделить логику между Java и Pascal.** Отклонено: два места, где живут
правила, — это гарантированное расхождение между ними.
