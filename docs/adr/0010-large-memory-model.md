# ADR-0010. Модель памяти проекта — large, стеки файберов в дальней куче

**Статус:** Принято
**Дата:** 2026-09-01
**Изменяет:** [ADR-0008](0008-cooperative-fibers.md) в части размещения стеков

## Контекст

ADR-0008 предполагал, что все стеки файберов лежат одним статическим массивом
в сегменте данных, а переключение меняет только `SP` при неизменном `SS`. Это
устраняет целый класс ошибок с сегментами и выглядело очевидно правильным.

Спайки S1 и S1b измерили цену этого решения. Результаты
(см. [PHASE0-FINDINGS.md](../PHASE0-FINDINGS.md)):

| Модель | SS = DS | MemAvail | Переключение |
|---|---|---|---|
| `tiny` | да | 35 086 Б | только `SP` |
| `small` | да | 52 498 Б | только `SP` |
| `medium` | да | 52 366 Б | только `SP` |
| `compact` | нет | 597 516 Б | `SS` и `SP` |
| `large` | нет | 596 188 Б | `SS` и `SP` |
| `huge` | нет | 595 020 Б | `SS` и `SP` |

Разница по доступной памяти — **одиннадцать раз**. При этом обе конструкции
переключения контекста прошли по 100 000 переключений без единой повреждённой
канарейки, с одинаковой измеренной глубиной стека (38 байт у простого файбера,
около 220 у файбера с рекурсией на шесть уровней).

В модели `medium` шестнадцать сессий по 4 КБ стека заняли бы 64 КБ — то есть
весь сегмент данных целиком, не оставив ничего ни куче, ни буферам. Пришлось бы
переносить сессионные арены в EMS и отображать страницы при каждом переключении
контекста.

## Решение

Модель памяти проекта — **`large`**: дальний код, дальние данные.

Стек каждого файбера выделяется из дальней кучи в собственном сегменте.
Указатель нормализуется: смещение сводится к младшим четырём битам, остальное
уходит в сегмент. `ContextSwitch` сохраняет и восстанавливает пару `SS:SP`;
запись в `SS` и в `SP` выполняется неразрывно, под запретом прерываний.

## Последствия

- Доступно **599 628 байт** вместо 52 366 — примерно 33 КБ на сессию при шестнадцати сессиях.
- EMS перестаёт быть несущей конструкцией и понижается до резерва под возможный кэш ленты. Спайк S4 теряет приоритет. Из [TURBOCORE.md](../TURBOCORE.md) §4 уходит целый ярус памяти и вся сложность с отображением страниц при переключении контекста.
- Переключение контекста дороже на две инструкции. На фоне обмена по последовательной линии это неизмеримо.
- Указатели становятся дальними, 4 байта вместо 2. Структуры данных немного растут, разыменование чуть дороже.
- Бинарник крупнее: 30 390 байт против 21 002 у той же программы в `medium`. Бюджет в 400 КБ из §12 не под угрозой.
- Возвращается класс ошибок, который `SS = DS` устранял: указатель на локальную переменную, переданный за пределы кадра, теперь указывает в чужой сегмент. Правило «указатель на локальную переменную не покидает кадр» из §13 становится не стилистикой, а требованием безопасности, и выносится в проверку линтера.
- Требуется дисциплина при работе с ассемблером: обращения к глобальным данным идут через `DS`, и `DS` обязан быть восстановлен до любого такого обращения.

## Рассмотренные альтернативы

**`medium` плюс EMS для сессионных арен.** Отклонено после измерения. Экономия —
две инструкции в одном месте; цена — работа с отображением страниц в каждом
выделении памяти и в каждом переключении контекста. Сложность размазывается по
всему коду вместо того, чтобы быть локализованной.

**`compact`.** Даёт ту же дальнюю кучу, но ограничивает код 64 КБ. Протокольный
стек, экранный движок и логика сессии в 64 КБ не поместятся, а если и
поместятся, то запаса на развитие не останется.

**`huge`.** Отличается от `large` поддержкой массивов больше 64 КБ ценой
нормализации указателей на каждом обращении. Таких массивов у нас нет.

**Уменьшить число сессий до четырёх и остаться в `medium`.** Отклонено:
подрывает главное обоснование фреймворка файберов из ADR-0008.
