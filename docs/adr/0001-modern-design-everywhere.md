# ADR-0001. Ни одна поверхность не выглядит старой

**Статус:** Принято
**Дата:** 2026-09-01

## Контекст

Проект намеренно собран из технологий разных эпох. Возникает соблазн подкрепить
это ретро-оформлением: ANSI-арт, вёрстка таблицами, псевдографика ради стиля.
Это дешёвый ход, который превращает инженерный эксперимент в костюмированную
вечеринку и обесценивает всё остальное.

## Решение

Каждая пользовательская поверхность оформляется по современным стандартам своей
среды. Веб — обычный продуктовый интерфейс 2026 года. Терминальный клиент — в
эстетике современных TUI (`btop`, `lazygit`), а не BBS девяностых. Внешний
наблюдатель не должен догадываться о содержимом бэкенда.

## Последствия

- Контраст между фасадом и устройством усиливается, а не размывается.
- Терминальный интерфейс дороже в разработке: аккуратная сетка, состояния, обработка изменения размера окна.
- Из бэклога удалены адаптеры, чья единственная ценность была ретро-визуальной: HTML 4.01 с фреймами, WML, ANSI-арт как фича, звук через PC-speaker.
- Протокольные адаптеры без визуальной составляющей (Gopher, Finger, IRC) сохраняются: они демонстрируют независимость домена от транспорта.
- Java-апплет из Tier C конфликтует с этим ADR и берётся последним, отдельным осознанным решением.

## Рассмотренные альтернативы

**Ретро-оформление везде.** Отклонено: шутка считывается за пять секунд, после
чего смотреть не на что.

**Смешанное оформление.** Отклонено: непоследовательность читается как небрежность.
