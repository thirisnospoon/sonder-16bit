# ADR-0004. CORBA/IIOP как внутренний канал между core и events

**Статус:** Принято
**Дата:** 2026-09-01

## Контекст

Сервису `events` для построения проекций и уведомлений нужны данные, которыми
владеет `core`. Прямое чтение чужих таблиц нарушает границу владения. Нужен
синхронный внутренний вызов. Одновременно требуется настоящее обоснование для
Java 8 — иначе выбор версии остаётся вкусовым.

## Решение

Обогащение события выполняется вызовом `core` по IIOP, контракт описан в
`contracts/idl/enrichment-v1.idl`, стабы порождаются `idlj`.

Java 8 — последний JDK, содержащий CORBA в составе платформы; в Java 11 она
удалена. Это превращает версию из предпочтения в требование.

## Последствия

- Граница владения данными соблюдена: `events` не читает таблицы `core`.
- При недоступности `core` дренаж outbox честно останавливается и ретраится, а не пишет неполные проекции.
- IIOP плохо переносит контейнерные сети: ORB зашивает адрес в IOR. Требуется явная настройка `ORBServerHost` и интеграционный тест внутри compose-сети (спайк S5).
- Обновление до Java 11+ становится невозможным без замены этого канала. Принимается сознательно.
- IDL — ещё один контракт в матрице кодогенерации, со своей стоимостью сопровождения.

## Рассмотренные альтернативы

**REST между сервисами.** Отклонено: работает, но не несёт нагрузки в замысле и
оставляет Java 8 без обоснования.

**RMI.** Отклонено: живёт и в современных JDK, поэтому не обосновывает версию.
Остаётся планом отхода по R5.

**Общая база на два сервиса.** Отклонено: разрушает границу владения — ровно то,
чего мы избегаем.
