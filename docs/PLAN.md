проверяемое утверждение, а не ощущение.

## Фаза 1. Каркас: репозиторий, контракты, CI

- Монорепозиторий по раскладке ниже.
- `contracts/` с первой версией `decider-v1.wsdl`, IDL, OpenAPI, `errors.yaml`.
- Кодогенерация во всех направлениях, включая заготовку `wsdl2pas`.
- CI на GitHub Actions: сборка, линт, тесты, проверка дрейфа контрактов, скан зависимостей.
- Одна команда поднимает всё локально.

**Ключевое решение этой фазы** — форма контракта. Каждая операция объявляет
команду, **состояние, необходимое для решения**, и форму решения. Ошибка здесь
дороже всех остальных: неполное объявление состояния означает, что ядро примет
решение по неполным данным, а обнаружится это в проде.

**Гейт Ф1 взят.** `./sonder bootstrap && ./sonder verify` проходит на чистой
машине без ручных шагов; из зависимостей нужен только Docker. Правка контракта
красит сборку до перегенерации стабов — проверка дрейфа сравнивает
сгенерированное с тем, что порождается из контрактов прямо сейчас.

Сделано:

- контракты: `decider-v1.wsdl`, `enrichment-v1.idl`, `social-v1.yaml`, `errors.yaml`;
- валидатор контрактов, 292 проверки, с самопроверкой на десяти реальных дефектах;
- кодогенерация: коды отказа на три языка, `wsdl2pas` с нуля, `operations.json`;
- сгенерированный Pascal не только компилируется под `i8086-msdos`, но и исполняется под DOSBox с вердиктом по TAP;
- CI на GitHub Actions: гейт на PR и ночная сборка со спайками.

**Готово.**

## Фаза 3. Доменное ядро на Pascal

**Самая важная фаза проекта, и она не требует ни транспорта, ни Java, ни базы.**

Решение есть чистая функция от команды и состояния, поэтому пишется и
проверяется прямым вызовом на нативном таргете. Инварианты из
[ARCHITECTURE.md](ARCHITECTURE.md) §6, коды отказов из `errors.yaml`,
порождение доменных событий.

- property-тесты инвариантов: ник, самоподписка, идемпотентность удаления, права ролей;
- golden-набор пар «команда + состояние → решение», зафиксированный в репозитории;
- фаззинг входных команд: ядро не имеет права упасть ни на каком входе, только отказать.

**Гейт Ф3:** покрытие ядра 100 %, property-тесты зелёные, фаззер сутки без
падений, golden-набор покрывает каждый код отказа. Всё — на нативном таргете,
за секунды.

**Оценка: 12 дней.**

## Фаза 4. TurboCore: рантайм

`tcfiber`, `tcsched`, `tcloop`, `tctimer`, `tcchan`, `Await`, `Panic`/longjmp,
сторожевой таймер.

**Гейт Ф4:** 16 файберов, 100 000 переключений, канарейки целы; намеренный
`Panic` в одном файбере не задевает остальные пятнадцать; залипший файбер
детектируется и попадает в лог; метрики планировщика экспортируются.

**Оценка: 10 дней.**

## Фаза 5. TurboCore: транспорт и протоколы

`tcport`, `tcframe`, `tcmux`, `tcxml`, `tcsoap`, готовый `wsdl2pas`.
NODE-7 становится SOAP-**сервером**.

Требования, вытекающие из измерений S2: кадр 512 байт, пакетирование
нескольких команд в один кадр, рукопожатие готовности перед первым обменом.

**Гейт Ф5:** полный SOAP-раунд-трип против замоканного клиента на нативном
таргете **и** на DOS-таргете; фаззер XML и кадров сутки без падений;
property-тест кадрирования зелёный.

**Оценка: 12 дней.**

## Фаза 6. Java: императивная оболочка

Схема БД, Flyway, write model, проекции read-model. REST-адаптер, сессии,
авторизация. SOAP-**клиент** к NODE-7, contract-first на CXF. Загрузка
состояния для каждой команды, сохранение решений с оптимистической блокировкой.

**Гейт Ф6:** ArchUnit подтверждает, что в Java нет ни одного доменного правила;
интеграционные тесты на Testcontainers проходят; конфликт версий агрегата
корректно приводит к переигрыванию команды.

**Оценка: 14 дней.**

## Фаза 7. Событийный конвейер

Триггер → `NOTIFY` → слушатель → дренаж outbox через `SKIP LOCKED` →
обогащение по IIOP → проекции → SSE. Идемпотентность, backoff, DLQ, poll-фолбэк.

**Гейт Ф7:** падение слушателя не теряет событий; дубликаты безвредны; порядок
внутри агрегата соблюдён; отставание в 10 000 событий рассасывается и видно на графике.

**Оценка: 10 дней.**

---

## Фаза 8. Gateway

Netty: мост «SOAP ↔ последовательная линия». Кадрирование, мультиплексирование,
пакетирование, рукопожатие, переподключение, экспорт метрик NODE-7.

**Гейт Ф8:** 16 команд в работе одновременно; обрыв линии приводит к
корректному переподключению без потери и без дублирования команд; backpressure
не теряет кадры.

**Оценка: 8 дней.**

## Фаза 9. Web

React 19, TypeScript, Vite, TanStack Query, типы из OpenAPI. Современный

**Ф3 — доменное ядро — не зависит ни от чего, кроме Ф1 и Ф2.** Его можно
писать параллельно со всей Java-веткой: контракт зафиксирован, транспорт не

проекта и самая дешёвая в разработке.

заглушки. Ф9 требует только Ф6.
