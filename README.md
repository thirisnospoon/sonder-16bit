# Sonder

Мини-соцсеть с современным вебом и намеренно нелепым бэкендом.

**Бизнес-логика исполняется шестнадцатибитным кодом под DOS.** Веб, база и
Java занимаются вводом-выводом: принять запрос, достать данные, сохранить
результат, разослать события. Решения — можно ли создать пост, свободен ли
ник, вправе ли модератор — принимает Turbo Pascal 7.

```
веб ──REST──► Java ──SOAP──► Turbo Pascal    решение
               │                  │
               └──── JDBC ────────┴──► Firebird ──POST_EVENT──► события
```

Форма — функциональное ядро и императивная оболочка. Ядро детерминировано и не
делает ввода-вывода не из эстетики, а потому что под DOS его сделать нечем: ни
драйвера базы, ни сетевого стека. Под Pascal написан собственный ООП-фреймворк
с кооперативной многозадачностью: линия медленная, и пока уходит один ответ,
следующая команда уже принимается.

Firebird происходит от Borland InterBase — того же дома, что и Turbo Pascal.
Веб построен на собственном реактивном слое на сигналах. Единственные внешние
зависимости проекта — Firebird, JDK и FPC.

> `Sonder` — рабочее имя продукта, `NODE-7` — кодовое имя DOS-ноды,
> `TurboCore` — имя Pascal-фреймворка. Меняются в одном месте.

## Главный принцип

**Ни одна поверхность не выглядит старой.** Веб — современный продуктовый
дизайн. У DOS-ноды поверхности нет вовсе: это ядро, а не клиент. Если не
заглядывать под капот, догадаться о содержимом невозможно. Абсурд живёт в
архитектуре, а не в оформлении.

## Второй принцип

**Каждая нелепость несёт нагрузку.** Ни одна древняя технология не стоит в
проекте ради вида: SOAP — это контракт, из которого генерируются стабы для трёх
языков; CORBA — единственный синхронный канал между двумя Java-сервисами;
кооперативные файберы — единственный способ конвейеризовать работу поверх
линии в 11.5 КБ/с; COBOL считает ночной свод, потому что потолок записи в
21,5 команды в секунду принадлежит линии, и всё, что можно снять с
оперативного пути, снимается ([ADR-0018](docs/adr/0018-cobol-batch-digest.md)).

Крайний случай — **Brainfuck**: он проверяет, что каждая запись свода ровно
380 байт. За одну сессию единицу измерения перепутали четырежды, и один раз
ошиблась сама проверка — `length()` в awk считает символы, а не байты, и
объявил негодными 6971 запись из 6972 при исправной выгрузке. Общее у всех
четырёх промахов — понятие «символ». У Brainfuck его нет: он читает байт и
прибавляет единицу, ошибиться в единице измерения ему нечем
([ADR-0019](docs/adr/0019-reclen-second-opinion.md)).

Проверка простая: если технологию убрать и ничего не сломается, она уходит.
Так из проекта уже вылетели EMS и XSLT-отрисовка — измерения показали, что они
не нужны.

## Как запустить

Из зависимостей нужен только Docker: весь тулчейн живёт в образах, на хосте не
устанавливается ничего.

```bash
./sonder bootstrap   # собрать образы: кросс-компилятор FPC, DOSBox, питон
./sonder up          # поднять систему целиком
./sonder verify      # прогнать все проверки, как в CI
./sonder help        # остальные цели
```

После `up` система открывается на <https://localhost:8443> — самоподписанный
сертификат, браузер выругается. TLS здесь не украшение: кука сессии объявлена
контрактом как `Secure`, и по обычному HTTP браузер выбросил бы её молча.

## Статус

**Система работает целиком.** Клик в браузере уходит командой по нульмодему в
шестнадцатибитное ядро под DOSBox, возвращается решением, событие уезжает в
outbox, дренаж доводит его до проекции, и пост появляется в ленте.

Гейты фаз 0–10 взяты, кроме накопительного: фазе 5 нужны сутки фаззинга.

| Что | Сколько |
|---|---|
| Проверки TurboCore и домена (Pascal, TAP) | 681, и обе на двух таргетах |
| Модульные проверки оболочки (Java) | 92 |
| Интеграционные против настоящего Firebird | 135 |
| Модульные проверки фронта (TypeScript) | 90 |
| Сценарии в настоящем браузере | 17 |

Измерено на живой системе, а не рассчитано:

| Величина | Значение |
|---|---|
| Потолок записи | **21,5 команды/с** без отказов, дальше `DECIDER_UNAVAILABLE` |
| Потолок чтения | **309 запросов/с** — чтение к ядру не ходит |
| Lighthouse | 100 · 100 · 96 · 100 |
| Доступность | уровень AA, нарушений axe-core нет |
| Сквозной след | один `trace_id` от заголовка ответа до строки лога NODE-7 |
| Возвращение после отказа базы | меньше секунды, само |
| Возвращение после обрыва линии | 40 с, само |

Подробности замеров — [docs/BENCHMARK.md](docs/BENCHMARK.md); что и чем
проверяется — [docs/ENGINEERING.md](docs/ENGINEERING.md) §2; что нашлось по
дороге — [docs/PLAN.md](docs/PLAN.md).

Спайки фазы 0, с которых всё началось, остались в
[docs/PHASE0-FINDINGS.md](docs/PHASE0-FINDINGS.md): 100 000 переключений

круговой обмен. Последнее число и стало потолком записи всего приложения.
